# シェーダー調整メモ

描画コードの変更は `basic.frag`、`sky.frag`、`post.frag`、`bright.frag`、`blur.frag` のみです。
今回の昼・夕焼けの再調整は、そのうち `basic.frag`、`sky.frag`、`post.frag` です。
頂点形式、uniform、C++の描画順、テクスチャ、保存形式は変更していません。
Solasの色付き照明・生成マテリアルの方向性を参考にした独自実装であり、Solasの移植ではありません。

## 照明と質感

- 太陽が低いほど大気を通る距離が長くなる近似を使い、太陽光の青・緑を減衰させます。
  明るさの時間変化は既存の `uSunIntensity` を維持し、昼はほぼ白い光になります。
- 空からの環境光は、空の一部分の色より彩度を抑えています。昼の石や影が青く染まりすぎない設定です。
- 夕焼けの暖色は太陽側の低空に集中させ、頭上の青と日没後の残照を分けて計算します。
  地平線の色は霧にも同じ関数を使います。太陽・月の大きさは昼・夕焼けの再調整前の設定に戻しています。
- 色付きBlock Lightは広い範囲の間接光、Point Lightは近距離の直接光として加算します。
- Point Lightは光源付近で発散しない逆二乗型の減衰と、半径端で滑らかにゼロになる窓を使います。
- 石には幅の広いGGXハイライトを加え、土・草はさらに粗くつやの少ない質感にします。
  アルベドの明るいピクセルを強い光沢に変えていた設定をやめ、乾いた石として扱います。
  拡散光と鏡面光の明るさの単位を揃え、法線の細かな変化によるハイライトのちらつきを抑えています。
- 既存のアルベドから小さな凹凸を推定します。本物の法線マップ・凹凸形状・視差ではありません。
- 凹凸参照はアトラスのタイル内に制限し、遠方では弱めます。ワールド座標の乱数模様は使いません。
- 松明の既存の炎領域と、ユーザー設定のオレンジEmission `5.5` は維持しています。
- Glowstoneの発光は既存のアトラスタイルから判定します。
- 夜は空の青みを弱く残し、空光がゼロの洞窟は非常に暗くします。
- 月光はSky Lightによる近似であり、月用のシャドウマップはありません。

## 後処理

- BloomはRGBの比率を維持して抽出し、赤・青の光も白くしなくてよいようにしています。
- Bloom強度はシェーダー内で抑え、床の照明と画面上のにじみを区別します。
- ぼかしは既存の回数・解像度のまま、線形フィルターの5参照で9タップ相当を計算します。
- トーンマッピングは従来のACES近似と色保持版を混ぜます。
  通常の面では色保持の比率を下げ、明るい光源では高くします。
  画面全体へ青い影・オレンジの明部を足すカラーグレーディングは外しました。
- 最終段でsRGB変換と1階調未満のディザーを行います。

質感計算にはテクスチャの追加4参照とGGX計算が必要です。
ぼかしの参照数は減りますが、ゲーム全体が高速になるとは限りません。
`DETAIL_STRENGTH = 0.0` にすると凹凸を無効にでき、定数伝播による不要処理の削除も期待できます。

## 調整箇所

`basic.frag` の冒頭の定数:

- `DETAIL_STRENGTH = 0.22`: 推定凹凸の強さ。0で無効。
- `BLOCK_LIGHT_STRENGTH = 0.85`: 広がるBlock Lightの強さ。
- `POINT_LIGHT_STRENGTH = 1.0`: Point Lightの強さ。

`MaterialRoughness()` の石の範囲は `0.82～0.74` です。
小さくするとつやが強く、大きくすると粗くなります。土・草は別の値です。
マテリアル推定は現在の32×16アトラスに対応しています。タイル配置を変えた場合は調整してください。

`post.frag`:

- `BLOOM_AMOUNT = 0.28`: 画面上のにじみ。
- `COLOR_PRESERVATION = 0.55`: 明るい光の色保持。通常の面は0.22から補間します。

## シェーダーだけでは追加していないもの

- 鏡面に周囲の物体そのものが映るSSR・レイトレーシング。
- 点光源の遮蔽影、光源ごとの正確な壁の遮蔽。
- 遮蔽物を考慮した体積光・ゴッドレイ。
- 新しい色の光源ブロック。現在C++は松明もGlowstoneもオレンジRGBを渡します。
- 光伝播タスク、チャンクロード順、複数光源のCPU側の色混合の変更。

空は軽量な解析式による近似です。実際の大気の多重散乱、気象、雲を再現するモデルではありません。
再調整でテクスチャ、レイマーチ、描画パスは増やしていません。

画像のような色付きハイライトは、入力されたRGBに応じて描けます。
紫・青・緑の光源をゲームに追加する場合や、上記の本格的な反射・影を追加する場合は、
C++側の変更を別途承諾してもらう必要があります。

## 検証・反映

`build/shader-qa/` の独立したPython/OpenGLテストで、実際の全7組のシェーダーを
コンパイル・リンクし、変更前後を同じ入力で描画しています。
比較画像はテスト用の場面です。実際のゲーム内スクリーンショットではありません。
テストの4色光源は検証用入力で、ゲームに追加したブロックではありません。
実際のゲームのFPSやチャンク伝播の正常性を保証するテストではありません。

今回の再調整の比較は `build/shader-qa/refine-results/` にあります。
左がこの再調整の直前、右が再調整後です。昼光のみ・夕焼け・夜の色付き照明を別々に比較しています。

```text
python build/shader-qa/validate.py --baseline refine-before --output refine-results
```

このテストにはNumPy、Pillow、ModernGL、glcontextとOpenGL対応GPUが必要です。
テスト用依存は `build/shader-qa/deps/` に置いてあり、ゲームの依存関係には追加していません。

CMakeの配布用assetsだけ更新する場合:

```text
cmake --build --preset windows-mingw --target glcraft_assets
```

アプリはシェーダーを起動時に読み込むため、完全に終了して起動し直してください。

## 設計を確認した参考資料

- [Filament: Physically Based Rendering](https://google.github.io/filament/main/filament.html): 粗さとGGX、拡散・鏡面反射の扱い。
- [Bruneton: Precomputed Atmospheric Scattering](https://ebruneton.github.io/precomputed_atmospheric_scattering/): 大気の透過と散乱の考え方。
  本実装はこの事前計算モデルの移植ではなく、既存の入力だけで動く簡易近似です。
